# 04 — Risk register

Ordered by expected damage. `P*` items are unknown-unknowns we must convert into measurements.

| id | risk | why it is credible here | mitigation / decision |
| --- | --- | --- | --- |
| **R-1** | **Silently wrong KV after restore** — a corrupted or mismatched host page produces plausible-but-wrong text, not an error | this exact engine family has a history of silent NaN (upstream #55766, sm_8x-class) and a wrong-divisor resume bug (#53142); we additionally carry 4 patches over a hybrid GDN tree. A clinical simulation that is silently wrong is worse than one that crashes | gate **G-1** (byte-exact + output-equivalence at temp 0, 50 prompts across 4 context lengths) before any traffic; keep `--kv-transfer-config` off in `last-good` so rollback is one restart |
| **R-2** | **Hybrid state may simply not be offloadable in this build** | GDN recurrent state is O(1) per checkpoint with a different page layout (this tree's unified 816-token page); `ssm_conv_transfer_utils.py` proves state *transfer* exists for NIXL, not that the CPU offload spec handles it with `inc` quantization + EP + MTP | decide with a cheap experiment (phase 2 G-1 / first boot), not with argument. If unsupported, the whole thesis pivots to attention-only tiers — still interesting, differently scoped |
| **R-3** | **PCIe contention degrades decode** — KV transfers on the same links that stream activations | our measured interference is severe in the analogue case: one 30K cold prefill storm → 9.2× short-request TTFT. Restoring 55 GiB is 4 links × 13.8 GiB of traffic | gate **G-4**; rate-limit promotions; never restore inside a decode-critical window; prefer restore-during-idle + JIT prefetch ahead of predicted return |
| **R-4** | **Cache thrash** — a policy that "keeps everything expensive" fills RAM, then ping-pongs RAM↔HBM and burns bandwidth | direct failure mode of value = recompute-cost-only policies; our RAM tier is only 6.7× HBM, not ∞ | the value function includes a pressure term and a transfer-cost term (docs/00 §4: λ_io); phase-0 replay tests exactly this at multiple RAM sizes |
| **R-5** | **Rollback/abort inconsistency** (arXiv 2608.15939): a *stateful* serving path that keeps inference state across a logical abort lets the model attend discarded content; reported flip in 25/63 audited cells with the tokens absent from the request | **corrected 2026-09-19 — my earlier claim that plain APC is exposed was wrong.** Exact-content matching cannot attend tokens absent from the request, so a stateless `P+Y` request cannot pull in cached `X`. Real exposures in our stack: (a) `/v1/responses` **is live on `:8002`** (HTTP 200) and our gateway's allowlist (`ndefy-model-router/main.go:67-72`) does *not* forward it — so the risk is direct host-network access to the engine, not product traffic; (b) **ACR itself**: promoting/restoring superseded branches, or any later move to non-prefix reuse; (c) our three abort paths matter only if a path assumes "cache cleared = state gone" | gate **G-2**; transaction-scoped invalidation as a first-class residency op (`acr.invalidate_tx`); keep `/v1/responses` off the gateway allowlist and consider binding `:8002` to loopback/`127.0.0.1`; audit whether any flow relies on transcript-clear semantics |
| **R-6** | **PHI at rest**: a persisted KV tier materializes patient conversation state as tensors on disk / remote pool — recoverable by anyone with file access, and *not* covered by transcript deletion | the medical project has real data-governance boundaries; KV is a lossy but often sufficient encoding of the conversation | default `secondary_tiers: []` (no storage tier — and docs/00 §4 already says it buys no latency); if ever enabled: encryption at rest, per-tenant `cache_salt` partitioning, retention TTL enforced by the tier, and an explicit exclusion of patient-role traffic |
| **R-7** | **Cost-model error propagates into policy** — `C_recompute` is contested (7.9K vs 41.7K tok/s, a 5.3× spread) and it is the numerator of every decision | see docs/00 §2 C-conflict | calibrate (T-0.5) before phase 1 exit; run every conclusion with both values and report the band; if the ordering of policies flips, say so loudly |
| **R-8** | **Novelty erosion** | recent cs.DC listing carried ≥4 adjacent papers (TOPAS/GraniKV/HBM-repartition/ReCache) in one week | headline claim narrowed to hybrid-state residency + correctness (docs/02 §2); re-verify at writing time (docs/02 §5) |
| **R-9** | **Window scarcity** — every engine-level test costs a ~5-minute restart of the machine hosting this session | 4×L20 is one engine; a second engine fails boot ("free 4.7 < desired 6.66") | bundle all engine tests into one promotion window with a scripted gate sequence; keep phases 0–1 restart-free by design |
| **R-10** | **Out-of-tree API churn** — vLLM logs *"Loading out-of-tree … This API is experimental and subject to change"* on exactly the seams we use | we already maintain a 4-patch chain against a pinned digest; a 5th moving surface raises maintenance cost | pin the package to the engine digest; a CI job that imports the ABCs and runs the policy unit tests against the image's `vllm` on every bump; keep our delta to *files added*, never files edited |
| **P-1** | block-size/page-layout mismatch (connector `block_size` vs the engine's real **816-token** unified attention/mamba page) | **partly resolved by log evidence** (816 confirmed, all ranks); the open half is whether an offloading connector may use a `block_size` that is a multiple/divisor of it and whether `prefix_match_unit` can be lowered on a hybrid tree | set the connector to 816 for G-1; separately measure whether a finer `--prefix-match-unit` shrinks rollback re-miss (see docs/05 F-9 — `MambaManager` does not opt into fine-grained hash lookup, so the gain may be capped by the recurrent group) |
| **P-2** | whether enabling a connector re-enables code paths our 4 patches fix (mamba align/resume kernels) | the patch chain is the stability basis; a connector changes scheduling | G-3 re-runs the full growing-prefix harness with connector on — we treat "connector on" as a new configuration needing its own evidence, not as a flag |

## Explicit non-goals

- No custom CUDA/Triton kernels; we use `swap_blocks_triton`/the connector's worker as shipped.
- No vLLM fork. Out-of-tree plugin only; if a hook is missing we prefer a small upstream PR or a
  custom manager class over editing engine files.
- No ML predictor in v0. Linear score + measured weights, with replay-based tuning; a learned
  hazard model only after ≥10⁵ real transitions.
- No storage tier for latency (docs/00 §4 says it cannot win here at 413 MB/s vs the 445 MB/s
  break-even).
